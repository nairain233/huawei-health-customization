# 华为运动健康 17.0.7.310 布局定位记录

## 版本与边界

目标仅为 `com.huawei.health` 17.0.7.310（versionCode `1700007310`）。依据来自目标 APK 的 JADX 产物与 MuMu12 `emulator-5554` 页面层级。服务端新下发且无法识别的内容保持显示。

`HealthAboutActivity` 不安装任何 Hook；仅“我的”列表中的 `IDS_settings_about` 入口可按配置过滤。

## 关键映射

“我的”营销容器只请求位置 ID `4168`（新品上市）和 `9013`（新人福利）。开关开启时在异步回调进入 View 生成前复制并过滤 Map；两个 ID 都移除后，宿主原有的 `removeAllViews()` 会使 `item_my_grid` 保持空容器，不留下营销卡片内容或空白卡片。其他位置 ID 原样保留。

“我的”行项目优先使用目标字符串资源名，不使用显示位置。17.0.7.310 的运行时资源表会把部分资源名压缩为数字，因此同时保留该版本核验后的 `R.string` ID 映射；未知 ID 仍保留显示。

未登录设备页使用 `DeviceFragment` 与添加设备卡；已登录页使用 `NewDeviceFragment` 父页、`ArkuiDeviceFragment` 设备内容和独立 `VMallFragment` 商城。旧页资源规则保留，新页按 `switch_device` / `switch_web`、委托根视图和标题条目分别处理。JADX 展示的 `defpackage.rxl` 等在 Dex 中实际为 `rxl` 等。设备与商城入口不会同时隐藏；隐藏当前子页前先切换到仍可见的子页。旧的 `device_card_list_more_add` 不再作为“添加设备”依据，避免误折叠多个区块。

运动页两态共用 `SportEntranceFragment`，五个子页内容由服务端异步装载。分类栏、搜索、菜单、Banner、快捷入口、计划槽、训练和课程区块按各自已核验资源或标题处理。计划页两张横向卡按标题与 `item_two_landscape_layout` 定位；户外跑步的概览、路线和操作按资源定位；瑜伽与健身共用 `normal_view_fitness`，须再核对当前选中子页才折叠对应项目。`resPosId=4040` 的 Knit 列表仅用于推荐页；其他子页不借用此编号。根视图使用弱引用布局回调，快捷入口绑定时恢复复用视图的原始状态，未知内容保持显示。

## 回归要求

- 总开关关闭时四页及底栏保持原样。
- 各解析路径至少单独验证一项，再验证每页“全部精简”。
- 底栏逐项隐藏后剩余项等宽重排；五项全隐藏时仍显示健康。
- 重复进入、返回、滚动、横竖屏和进程重启后无复用污染、空白、崩溃或 ANR。
- 抽查运动记录、添加设备、登录、同步与权限流程未被修改。
