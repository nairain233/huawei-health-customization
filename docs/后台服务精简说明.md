# 后台服务精简实现与验证

## 目标与依据

目标包 `com.huawei.health`，仅在首包主进程、Application.attach 完成后安装；不按宿主版本号限制，实际校验 ContextImpl 签名。Service 的具体类名来自设备上实际安装的 APK 声明，不内置未经核验的类名或用途判断。仓库“调试”中有 17.0.7.310 APK；当前无可用测试设备，具体服务的业务影响仍待确认。

Hook 使用 Android 的 ContextImpl 服务公共内部入口，已核验签名来源：

- [AOSP Android 9](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-9.0.0_r1/core/java/android/app/ContextImpl.java)：`startServiceCommon(Intent, boolean, UserHandle)`；`bindServiceCommon(Intent, ServiceConnection, int, Handler, UserHandle)`。
- [AOSP Android 10](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-10.0.0_r1/core/java/android/app/ContextImpl.java)：绑定入口新增 `String instanceName` 和 `Executor` 参数。
- [AOSP Android 16 QPR2](https://android.googlesource.com/platform/frameworks/base/+/android16-qpr2-release/core/java/android/app/ContextImpl.java)：绑定入口 flags 为 `long`；普通/前台启动及多种绑定重载汇入上述入口。

解析同时校验 `unbindService(ServiceConnection): void` 与 `getOuterContext(): Context`，遇到未知签名、重复候选或解析异常整项跳过。签名兼容不代表所有厂商系统已完成真机验证。

## 数据与降级

独立总开关 `service_block.enabled` 默认 false；普通功能开关保存在 `service_block.presets`，调试模式保存在 `service_block.debug_mode`（默认 false），逐服务规则继续保存在 `service_block.components`。组件规范化为 `包名/完整类名`，仅接受目标包；允许服务实现类位于其他命名空间。配置快照在每次目标进程启动时读取，匹配同时要求组件存在于当前 APK 服务声明中。调试模式关闭时旧的逐服务规则保留但暂停生效；开启后才与预设规则合并。非显式 Intent、其他包和未选服务保持原行为。

普通预设仅包含当前 APK 中有明确调用证据的用途：应用与模块更新（`UpdateService`、`HwUpdateService`、`ScaleUpdateService`）、设备音乐同步（`SyncMusicService`）、训练计划下发（`PlanSendService`）和表盘试用（`TryOutWatchFaceService`）。它们默认关闭，组件缺失时跳过。`PhoneService` 同时承担设备连接与通知协同，云端同步涉及 WorkManager 多进程任务，因此暂不提供普通开关；未经真机验证不得声称可安全关闭。

## 主要业务分组

页面将服务合并为三个区域。低耦合区域包含“应用更新后台服务”（应用更新与模块更新）、“设备辅助后台服务”（音乐同步、训练计划下发、表盘试用）和“运动辅助后台服务”（离线地图、运动语音）。核心区域包含“设备连接与协同”“设备固件更新”“运动记录”“健康与训练同步”“消息与计划提醒”“应用核心驻留”“钱包与支付”“睡眠与专项健康”“设备诊断”。核心组默认关闭，启用前需确认设备连接、运动记录、健康数据、支付或提醒可能受到影响；当前尚未完成真机验证。

| 区域 | 业务组 | 主要组件/依据 | 屏蔽影响 | 状态与恢复 |
|---|---|---|---|---|
| 低耦合 | 应用更新、设备辅助、运动辅助 | 反编译服务方法和 Manifest 声明 | 更新、音乐传输、计划下发、表盘试用、地图或语音可能受影响 | 默认关闭；关闭组并彻底重启宿主恢复 |
| 核心 | 设备连接与协同、固件更新、运动记录、健康同步 | 设备管理、Track、DataSync、WearEngine 等服务 | 连接、重连、轨迹、记录、同步或固件升级可能失败 | 默认关闭；仅建议验证后使用 |
| 核心 | 消息提醒、核心驻留、钱包支付、睡眠诊断 | 推送、Daemon、钱包、睡眠和诊断服务 | 通知、初始化、支付、睡眠记录或诊断可能失效 | 未真机验证；关闭组并重启恢复 |
| 调试 | 自定义服务组件 | 当前 APK 声明的完整服务目录 | 影响取决于具体组件，未知职责默认放行 | 调试模式关闭时规则保留但暂停 |

业务组只拦截当前 APK 已声明的组件；组间重复组件在有效集合中去重。JobService 的系统调度、广播、PendingIntent、直接 Binder、其他进程以及已经运行的服务不受该机制完整控制。文档中的职责判断来自 17.0.7.310 反编译代码或 Manifest，均不等同于已证明可安全关闭。

开启后服务启动返回 null、绑定返回 false，不构造假的连接或成功状态。绑定记录只持有 Context 与 ServiceConnection 的弱引用，按对象身份隔离。未被拦截的绑定即使返回 false 也保留系统解绑；被拦截的连接仍先尝试真实解绑，兼容早期已有连接，仅对纯拦截记录的未注册解绑异常降级。

三个 Hook 作为事务安装，并对已核验的公共调用包装方法去优化，避免 common 入口被内联绕过；全部完成后才激活。安装或去优化失败时逆序卸载，卸载失败的残留入口保持不激活。异常日志仅含固定原因和异常类型，不输出宿主 Intent、异常消息或栈。

页面在工作线程查询包信息和同步提交配置；保存失败尝试恢复 RemotePreferences 的旧值（包括其乐观更新的本地缓存）。无法确认恢复时禁用编辑并要求恢复连接后刷新核对。配置状态不等价于设备 Hook 安装状态。

## 覆盖范围与限制

不修改组件启用状态，不请求 Root，不 Hook 系统进程，不停止已运行服务。系统、其他应用、子进程、直接 Binder、PendingIntent 和 attach 完成前的调用不保证拦截。不管理广播及任务调度，JobService 虽可能在服务列表中出现，其系统调度不受该功能控制。

服务被拒绝可能造成通知、设备连接、同步等功能不可用；不能保证目标应用处理所有失败返回值。恢复方式是撤销对应规则或关闭独立总开关，并彻底重启运动健康两次。

## 验证清单

自动化覆盖：配置默认值及布局开关独立性、组件规范化与精确匹配、配置损坏、写入回滚、已消失规则、搜索筛选、绑定状态隔离、安装事务回滚；现有守卫测试覆盖版本、主进程与幂等性。Compose 测试覆盖首页入口、搜索、筛选、逐项选择、清空及失败状态。

设备验证尚未执行，交付前或安装后需在已支持目标版本和 LSPosed API 102 环境核验：

1. 默认关闭时登录、首页、运动记录、设备连接、同步保持原行为。
2. 选定一个已分析服务后，普通启动和前台启动返回 null，绑定返回 false；未选服务与其他包服务正常。
3. 被拒绝绑定之后解绑、重复绑定、不同 Context 复用同一连接、真实与拦截绑定混合均无模块引入的未注册异常。
4. 页面反复进入、旋转、返回、搜索筛选及长列表滚动后配置一致；配置服务断开与写入失败有明确提示。
5. 撤销规则并重启恢复放行；子进程和未知系统签名不安装服务拦截。不同宿主版本仍需检查组件声明与设备业务行为。
6. 检查 LSPosed 安装日志和业务表现，记录所选服务的实际影响；不得将未测试的服务推荐为安全精简项。
